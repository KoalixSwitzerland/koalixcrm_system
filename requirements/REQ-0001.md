# REQ-0001: Das System stellt ein einheitliches kanonisches Produktobjekt bereit

## Lizenzseite
Open-Source-Backend (`/app/koalixcrm`)

## Quelle
ADR-0003 (Produkt-Katalog-Backbone)

## Why
Das bisherige Split-Modell `ProductType`/`Product` erzeugt semantischen Overhead, weil `Product`
keinen eigenen Inhalt trägt. Ein einziges kanonisches Objekt `Product` ist Voraussetzung dafür,
dass Klassifizierung (ADR-0004), Preislogik (ADR-0005), Stücklisten (ADR-0006) und
Dienstleistungsprofil (ADR-0007) typsicher am selben Ankerpunkt befestigt sind.

## Beschreibung
Das Modell `Product` ist das kanonische Stammdatenobjekt des Produktkatalogs. Es trägt `sku`,
`gtin` (GS1 GTIN), `mpn` (Hersteller-Artikelnummer), ein `kind`-Enum mit den Werten `SERVICE`,
`TRADING_GOOD`, `MANUFACTURED_GOOD`, `KIT` und `RAW_MATERIAL`, einen `lifecycle_status`, eine
Basismaßeinheit (`base_uom`, FK auf `core.Unit`), eine Steuerklasse (`tax_class`, FK auf
`core.Tax`), einen `brand`-Wert sowie Audit-Felder. `Product` ist workspace-scoped und erbt den
`WorkspaceScopedModel`-Mechanismus: "Tenant-owned data inherits `WorkspaceScopedModel` and is
filtered by `request.active_workspace`" (ADR-0001).

Das frühere leere `Product`-Hüllenmodell entfällt; seine Identifikationsfunktion übernimmt
`ProductVariant`.

## Acceptance Criteria

### AC-1: Pflichtfelder und Eindeutigkeit
- [ ] Jedes `Product`-Objekt trägt genau einen `kind`-Wert aus der Menge `{SERVICE, TRADING_GOOD, MANUFACTURED_GOOD, KIT, RAW_MATERIAL}`.
- [ ] Jedes `Product`-Objekt trägt genau einen `lifecycle_status`.
- [ ] Die Kombination `(workspace, sku)` ist eindeutig; das System weist eine zweite Anlage mit derselben Kombination ab.
- [ ] Ein `Product`-Objekt ohne `kind` wird vom System abgewiesen.

### AC-2: Workspace-Isolation
- [ ] Jede Datenbankabfrage auf `Product` filtert automatisch nach `workspace`; kein `Product` eines anderen Workspace ist im Ergebnis enthalten.
- [ ] Ein API-Request ohne gültigen `active_workspace`-Kontext erhält keinen `Product`-Datensatz zurück.
- [ ] Ein automatisierter Test verifiziert, dass ein `Product` aus Workspace A nicht in Abfragen aus Workspace B erscheint.

### AC-3: Identifikatoren
- [ ] `gtin` wird als GS1 GTIN-14-kompatibler Wert gespeichert.
- [ ] `mpn` (Manufacturer Part Number) ist optional und auf Feldebene dokumentiert.

### AC-4: Beziehungen zu nachgelagerten Entitäten
- [ ] `Product` trägt einen optionalen FK auf `ProductFamily`; `ProductFamily` trägt keinen FK auf `Product`.
- [ ] `ProductVariant` trägt einen FK auf `Product` (ADR-0021: "`ProductVariant` trägt einen FK auf `Product` (nicht auf `ProductFamily`)").
- [ ] `ProductTranslation` trägt einen FK auf `Product`.
- [ ] `ProductMedia` trägt einen FK auf `Product` (produktweite Medien) oder einen FK auf `ProductVariant` (variantenspezifische Medien); der effektive Medien-Pool einer Variante ist die Vereinigungsmenge beider Ebenen (ADR-0021).
- [ ] Das Löschen eines `Product` schlägt fehl, wenn noch abhängige `ProductVariant`-, `ProductTranslation`- oder produktweite `ProductMedia`-Objekte existieren (referentielle Integrität).

## Quality Attributes
- **Skalierung**: Das System unterstützt mindestens 10 000 `Product`-Objekte pro Workspace ohne Degradation der API-Antwortzeiten (Threshold: p95 < 500 ms für eine paginierte Listenabfrage mit 50 Einträgen; gemessen ohne Attributfilter).
- **Datenintegrität**: Der `kind`-Enum-Wert ist unveränderlich, sobald abhängige Objekte (z. B. `BillOfMaterials` für `MANUFACTURED_GOOD`, `ServiceProfile` für `SERVICE`) existieren.

## Betroffene Komponenten
- Backend: `koalixcrm/products/models/product.py`, zugehörige DRF-Serializer und ViewSets
- Frontend: Produktlisten- und Produktdetailseite (liest ausschließlich über DRF-Endpunkte)
- Deployment: keine Infrastrukturändung

## Nicht im Scope dieser Anforderung
- Die Migrationsstrategie von `ProductType` zu `Product` (blockiert durch OQ-0002).
- Routing-/Arbeitsplanmodelle für Fertigungssteuerung (Gegenstand eines separaten ADR).
- Das Sperren des `kind`-Felds auf Datenbankebene (keine Datenbankconstraint für diese Invariante laut ADR-0006-Entscheidungstext; Durchsetzung in der Applikationsschicht).
