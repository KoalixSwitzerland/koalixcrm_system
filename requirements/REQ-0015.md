# REQ-0015: Das System modelliert Stücklisten nach ISA-95 Part 2 für Fertigprodukte und Kits

## Lizenzseite
Open-Source-Backend (`/app/koalixcrm`)

## Quelle
ADR-0006 (Beschaffung und Stücklisten)

## Why
Fertigende Mandanten benötigen eine strukturierte, datenbankgeführte Stückliste mit referentieller
Integrität auf Komponentenebene. Eine JSON-Struktur in `Product` bietet keine referentielle
Integrität, keinen direkten Einheitenbezug und keine Unterstützung für Alternativkomponenten.
ISA-95 Part 2 ist der Industriestandard für diese Struktur.

## Beschreibung
`BillOfMaterials` (workspace-scoped) repräsentiert eine Stückliste für ein `Product` mit
`kind = MANUFACTURED_GOOD`. `BomItem` (workspace-scoped) hält Komponenten-Produkt (FK auf
`Product`), Menge, Ausschuss-Prozentsatz und Alternativkomponenten. Die Strukturierung folgt
ISA-95 Part 2.

Die Applikationsschicht erzwingt die Invariante, dass `BillOfMaterials` ausschließlich für
`Product` mit `kind ∈ {MANUFACTURED_GOOD, KIT}` angelegt wird, da das Datenbankschema diese
Einschränkung nicht strukturell abbildet. Workspace-scoped Entitäten erben den
`WorkspaceScopedModel`-Mechanismus: "Tenant-owned data inherits `WorkspaceScopedModel` and is
filtered by `request.active_workspace`" (ADR-0001).

## Acceptance Criteria

### AC-1: BillOfMaterials-Grundregeln
- [ ] `BillOfMaterials` trägt einen FK auf `Product`.
- [ ] Das System weist eine `BillOfMaterials` ab, deren `Product` einen `kind`-Wert aus `{SERVICE, TRADING_GOOD, RAW_MATERIAL}` trägt (erlaubt sind ausschließlich `MANUFACTURED_GOOD` und `KIT`).
- [ ] Die Prüfung der `kind`-Invariante erfolgt in der Applikationsschicht (Serializer-Validator oder Service).
- [ ] Ein `Product` hat höchstens eine `BillOfMaterials` (1:1-Constraint).

### AC-2: BomItem-Grundregeln
- [ ] `BomItem` trägt einen FK auf `BillOfMaterials`, einen FK auf das Komponenten-`Product`, eine positive Dezimalzahl als Menge, einen FK auf `core.Unit` für die Mengeneinheit und einen optionalen Ausschuss-Prozentsatz (0–100 %).
- [ ] `BomItem` unterstützt mindestens eine Alternativkomponente als optionalen FK auf ein zweites `Product`.
- [ ] Ein `BomItem` ohne FK auf eine existierende `BillOfMaterials` wird abgewiesen.
- [ ] Das Komponenten-`Product` eines `BomItem` darf nicht dasselbe Objekt sein wie das Produkt der übergeordneten `BillOfMaterials` (keine Selbstreferenz).

### AC-3: Workspace-Isolation
- [ ] Jede Datenbankabfrage auf `BillOfMaterials` und `BomItem` filtert automatisch nach `workspace`.
- [ ] Ein automatisierter Test verifiziert, dass `BillOfMaterials`- und `BomItem`-Einträge aus Workspace A nicht in Abfragen aus Workspace B erscheinen.

### AC-4: Referentielle Integrität
- [ ] Das Löschen eines `Product`, das als Hauptprodukt einer `BillOfMaterials` fungiert, schlägt fehl, wenn noch `BomItem`-Einträge existieren.
- [ ] Das Löschen eines `Product`, das als Komponente in einem `BomItem` referenziert wird, schlägt fehl.

## Quality Attributes
- **Datenintegrität**: Die `kind ∈ {MANUFACTURED_GOOD, KIT}`-Invariante wird bei jeder Anlage und jeder Änderung von `BillOfMaterials` geprüft.
- **Interoperabilität**: Die `BillOfMaterials`/`BomItem`-Struktur ist über den DRF-Endpunkt als flaches oder verschachteltes JSON exportierbar, das einer ISA-95-Part-2-konformen Darstellung entspricht.

## Betroffene Komponenten
- Backend: `koalixcrm/products/models/bill_of_materials.py`, `bom_item.py`, kind-Validator, DRF-Serializer und ViewSet
- Frontend: Stücklisten-Viewer und -Editor in der Produktdetailansicht (über DRF-Endpunkte)
- Deployment: keine Infrastrukturänderung

## Nicht im Scope dieser Anforderung
- Routing-/Arbeitsplan-Modelle für Fertigungssteuerung (Gegenstand eines separaten ADR laut ADR-0006).
- MRP-/ERP-Export-Integrationen.
- Mehrstufige Stücklisten (Stücklisten von Stücklisten) — das Modell erlaubt es strukturell, aber die Traversal-Tiefe ist nicht begrenzt; Performance-Implikationen sind Gegenstand eines separaten QAS.
