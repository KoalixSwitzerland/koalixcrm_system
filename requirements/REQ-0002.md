# REQ-0002: Das System strukturiert Produkte in Familien und Varianten

## Lizenzseite
Open-Source-Backend (`/app/koalixcrm`)

## Quelle
ADR-0003 (Produkt-Katalog-Backbone)

## Why
Für Multi-Tenant-Plattformen mit 10 000+ SKUs muss die Identifikation auf SKU-Ebene sauber von
den Stammdaten getrennt sein. `ProductFamily` gruppiert eine Produktlinie; `ProductVariant` hält
eine Zeile pro tatsächlicher SKU mit Varianten-Achsen-Werten.

## Beschreibung
`ProductFamily` (workspace-scoped) fasst alle Varianten einer Produktlinie zusammen. Sie trägt
einen Namen und ist dem `workspace` zugeordnet.

`ProductVariant` (workspace-scoped) repräsentiert eine einzelne handelbare SKU. Sie trägt einen
FK auf `ProductFamily`, eine eigene `sku` und die Varianten-Achsen-Werte (z. B. Farbe × Größe).
Workspace-scoped Entitäten erben den `WorkspaceScopedModel`-Mechanismus: "Tenant-owned data
inherits `WorkspaceScopedModel` and is filtered by `request.active_workspace`" (ADR-0001).

## Acceptance Criteria

### AC-1: ProductFamily-Grundregeln
- [ ] Jede `ProductFamily` gehört zu genau einem Workspace.
- [ ] Jede Datenbankabfrage auf `ProductFamily` filtert automatisch nach `workspace`.
- [ ] Der Name einer `ProductFamily` ist innerhalb eines Workspace eindeutig.

### AC-2: ProductVariant-Grundregeln
- [ ] Jede `ProductVariant` trägt einen FK auf `ProductFamily`.
- [ ] Die Kombination `(workspace, sku)` ist über alle `ProductVariant`-Objekte eindeutig.
- [ ] Eine `ProductVariant` ohne FK auf eine existierende `ProductFamily` wird vom System abgewiesen.

### AC-3: Varianten-Achsen
- [ ] `ProductVariant` speichert mindestens einen Varianten-Achsen-Wert (z. B. Farbe, Größe) als strukturiertes Feld.
- [ ] Zwei Varianten derselben Familie mit identischen Achsenwert-Kombinationen werden vom System abgewiesen.

### AC-4: Workspace-Isolation
- [ ] Ein automatisierter Test verifiziert, dass `ProductFamily`- und `ProductVariant`-Objekte aus Workspace A nicht in Abfragen aus Workspace B erscheinen.

## Quality Attributes
- **Skalierung**: Das System unterstützt mindestens 100 `ProductVariant`-Einträge pro `ProductFamily` ohne Degradation der Listenabfrage.
- **Datenintegrität**: Das Löschen einer `ProductFamily` schlägt fehl, wenn noch `ProductVariant`-Objekte mit FK darauf existieren.

## Betroffene Komponenten
- Backend: `koalixcrm/products/models/product_family.py`, `product_variant.py`, zugehörige Serializer und ViewSets
- Frontend: Variantenauswahl in Produktdetail- und Listenansicht (über DRF-Endpunkte)
- Deployment: keine Infrastrukturänderung

## Nicht im Scope dieser Anforderung
- Die interne Darstellung von Varianten-Achsen im Frontend-UI (Gegenstand der Frontend-Anforderungen).
- Preislogik auf Variantenebene (Gegenstand von REQ-0010, ADR-0005).
