# REQ-0013: Das System speichert produktspezifische Maßeinheitenkonversionen datenbankgeführt

## Lizenzseite
Open-Source-Backend (`/app/koalixcrm`)

## Quelle
ADR-0005 (Preisgestaltung und Maßeinheiten)

## Why
Einheitenkonversionen (z. B. Verkaufseinheit Stück ↔ Lagereinheit Karton à 12) sind
produktspezifisch und variieren je Hersteller und Verpackungsform. Hardkodierte Konversionswerte
im Anwendungscode erzeugen Deploymentaufwand bei jeder Verpackungsänderung.

## Beschreibung
`UnitOfMeasureConversion` (workspace-scoped) hält produktspezifische Einheitenumrechnungen mit
FK auf `Product` und je einem FK auf Quell- und Ziel-`core.Unit`. Der Konversionsfaktor ist eine
Dezimalzahl. Workspace-scoped Entitäten erben den `WorkspaceScopedModel`-Mechanismus: "Tenant-owned
data inherits `WorkspaceScopedModel` and is filtered by `request.active_workspace`" (ADR-0001).

## Acceptance Criteria

### AC-1: Datenbankstruktur
- [ ] `UnitOfMeasureConversion` trägt einen FK auf `Product`, einen FK auf die Quelleinheit (`from_unit`), einen FK auf die Zieleinheit (`to_unit`) und einen positiven Dezimal-Konversionsfaktor.
- [ ] Die Kombination `(product, from_unit, to_unit)` ist eindeutig; das System weist eine zweite Anlage mit derselben Kombination ab.
- [ ] Ein Konversionsfaktor von null oder kleiner wird vom System abgewiesen.

### AC-2: Umkehrbarkeit
- [ ] Wird eine Konversion `(product, A → B)` mit Faktor `f` gespeichert, liefert das System auf Anfrage die Umkehrkonversion `(product, B → A)` mit Faktor `1/f`.

### AC-3: Workspace-Isolation
- [ ] Jede Datenbankabfrage auf `UnitOfMeasureConversion` filtert automatisch nach `workspace`.
- [ ] Ein automatisierter Test verifiziert, dass `UnitOfMeasureConversion`-Einträge aus Workspace A nicht in Abfragen aus Workspace B erscheinen.

### AC-4: Determinismus
- [ ] Die Konversionsberechnung ist eine reine Funktion; bei identischen Eingaben (Produktinstanz, from_unit, to_unit, Menge) liefert sie immer dasselbe Ergebnis.

## Quality Attributes
- **Datenintegrität**: Das Löschen eines `Product` schlägt fehl, wenn noch `UnitOfMeasureConversion`-Einträge darauf verweisen.
- **Determinismus**: Die Konversionsberechnung produziert bei identischen Eingaben bitgenaue, identische Ergebnisse.

## Betroffene Komponenten
- Backend: `koalixcrm/products/models/uom_conversion.py`, Konversionsservice, DRF-Serializer und ViewSet
- Frontend: Einheitenkonversionsverwaltung in der Produktdetailansicht (über DRF-Endpunkte)
- Deployment: keine Infrastrukturänderung

## Nicht im Scope dieser Anforderung
- Globale Einheitenkonversionstabellen in `core.Unit` (ADR-0005 hat diese Architektur explizit abgelehnt).
- Kettenkonversionen über mehr als eine Zwischeneinheit (z. B. Stück → Karton → Palette).
