# REQ-0003: Das System speichert Produktbeschreibungen in mehreren Sprachen mit Fallback-Kette

## Lizenzseite
Open-Source-Backend (`/app/koalixcrm`)

## Quelle
ADR-0003 (Produkt-Katalog-Backbone)

## Why
Mandanten im deutschsprachigen Raum und internationale Kunden benötigen Produktbezeichnungen,
Kurzbeschreibungen und Langbeschreibungen in mehreren Sprachen. Fehlt eine Übersetzung für eine
angeforderte Sprache, muss das System auf eine definierte Fallback-Sprache zurückfallen, damit
keine Leerfelder an den API-Consumer geliefert werden.

## Beschreibung
`ProductTranslation` (workspace-scoped) speichert je Sprachcode eine mehrsprachige Bezeichnung,
eine Kurzbeschreibung und eine Langbeschreibung zu einem `Product`. Das System liefert für jeden
Sprachanfrage eine Übersetzung gemäß einer definierten Fallback-Kette. Workspace-scoped Entitäten
erben den `WorkspaceScopedModel`-Mechanismus: "Tenant-owned data inherits `WorkspaceScopedModel`
and is filtered by `request.active_workspace`" (ADR-0001).

## Acceptance Criteria

### AC-1: Datenbankstruktur
- [ ] `ProductTranslation` trägt einen FK auf `Product`, einen BCP-47-konformen `language_code`, eine `name`-Bezeichnung, eine `short_description` und eine `long_description`.
- [ ] Die Kombination `(product, language_code)` ist eindeutig; das System weist eine zweite Übersetzung für dieselbe Kombination ab.

### AC-2: Fallback-Kette
- [ ] Wird für eine Sprachanfrage keine `ProductTranslation` gefunden, liefert das System die Übersetzung der workspace-weit konfigurierten Fallback-Sprache.
- [ ] Existiert auch für die Fallback-Sprache keine Übersetzung, liefert das System die erste vorhandene Übersetzung des Produkts.
- [ ] Existiert keine einzige Übersetzung für das Produkt, liefert das System einen leeren String für alle Textfelder; das Produkt-Objekt selbst wird nicht unterdrückt.
- [ ] Die Fallback-Kette ist in der API-Dokumentation beschrieben.

### AC-3: Workspace-Isolation
- [ ] Jede Datenbankabfrage auf `ProductTranslation` filtert automatisch nach `workspace`.
- [ ] Ein automatisierter Test verifiziert, dass `ProductTranslation`-Objekte aus Workspace A nicht in Abfragen aus Workspace B erscheinen.

### AC-4: Sprachcode-Validierung
- [ ] Das System weist einen `language_code` ab, der nicht dem BCP-47-Format entspricht.

## Quality Attributes
- **Skalierung**: Das System unterstützt mindestens 10 Sprachvarianten pro Produkt ohne Degradation der Einzelprodukt-Abfrage.
- **Korrektheit**: Die Fallback-Kette wird deterministisch aufgelöst; bei identischen Eingaben liefert das System immer dieselbe Übersetzung.

## Betroffene Komponenten
- Backend: `koalixcrm/products/models/product_translation.py`, Fallback-Logik im Serializer oder Service, DRF-ViewSet
- Frontend: Produktbezeichnungs- und Beschreibungsfelder in Listen und Detailansicht (über DRF-Endpunkte, Sprache per Accept-Language-Header oder Query-Parameter)
- Deployment: keine Infrastrukturänderung

## Nicht im Scope dieser Anforderung
- Übersetzungsverwaltungs-UI (Gegenstand von UC-0003).
- Automatische maschinelle Übersetzung.
- Übersetzungen für andere Entitäten als `Product` (z. B. `AttributeDefinition`-Labels).
