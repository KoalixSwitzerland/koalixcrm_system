# REQ-0005: Das System erzwingt den Lifecycle-Status von Produkten

## Lizenzseite
Open-Source-Backend (`/app/koalixcrm`)

## Quelle
ADR-0003 (Produkt-Katalog-Backbone)

## Why
Ohne definierten Lifecycle-Status können Produkte in beliebigem Zustand in Angeboten,
Aufträgen und Rechnungen referenziert werden. Ein maschinenlesbarer `lifecycle_status` ermöglicht
der Applikationsschicht, nur freigabereife Produkte in kommerzielle Dokumente aufzunehmen.

## Beschreibung
`Product.lifecycle_status` ist ein Enum, das den aktuellen Zustand eines Produkts im
Produktlebenszyklus beschreibt. Die Applikationsschicht und der DRF-Endpunkt setzen auf
`lifecycle_status` basierende Einschränkungen durch, z. B. indem nur Produkte mit dem Status
`ACTIVE` in neue kommerzielle Dokumente aufgenommen werden können.

## Acceptance Criteria

### AC-1: Statuswerte
- [ ] `lifecycle_status` kennt mindestens die Werte `DRAFT`, `ACTIVE`, `DISCONTINUED` und `ARCHIVED`.
- [ ] Jedes `Product`-Objekt trägt genau einen `lifecycle_status`.
- [ ] Ein `Product` ohne `lifecycle_status` wird vom System abgewiesen.

### AC-2: Statusübergänge
- [ ] Der Übergang von `ARCHIVED` zurück zu `ACTIVE` wird vom System abgewiesen.
- [ ] Der Übergang von `DISCONTINUED` zu `DRAFT` wird vom System abgewiesen.
- [ ] Alle erlaubten Statusübergänge sind in der API-Dokumentation als abschließende Liste angegeben.

### AC-3: Einschränkung in kommerziellen Dokumenten
- [ ] Das System verweigert die Aufnahme eines Produkts mit `lifecycle_status != ACTIVE` in ein neu erstelltes kommerzielles Dokument (Angebot, Auftrag, Rechnung).
- [ ] Bestehende kommerzielle Dokumente, die ein Produkt referenzieren, das nachträglich auf `DISCONTINUED` oder `ARCHIVED` gesetzt wird, bleiben unverändert erhalten.

## Quality Attributes
- **Datenintegrität**: Statusübergänge werden transaktional durchgesetzt; ein teilweise ausgeführter Übergang hinterlässt keinen inkonsistenten Status.

## Betroffene Komponenten
- Backend: `koalixcrm/products/models/product.py` (lifecycle_status-Feld), Transitionslogik im Service oder im Serializer-Validator
- Frontend: Statusanzeige und Statuswechsel-UI in der Produktdetailansicht (über DRF-Endpunkte)
- Deployment: keine Infrastrukturänderung

## Nicht im Scope dieser Anforderung
- Workflow-Genehmigungen für Statusübergänge (z. B. Vier-Augen-Prinzip).
- Automatische Archivierung nach Ablaufdatum.
