# REQ-0009: Das System verwaltet typisierte Attributdefinitionen mit Scope, Validierungsregeln und Gruppen

## Lizenzseite
Open-Source-Backend (`/app/koalixcrm`)

## Quelle
ADR-0004 (Klassifizierung und erweiterbare Attribute)

## Why
Mandanten aus unterschiedlichen Branchen benötigen unterschiedliche Pflichtfelder ohne
Code-Deploy. Nur typisierte `AttributeDefinition`-Einträge mit B-Tree-indizierbaren Wertetabellen
ermöglichen performante Attributfilter bei 10 000+ SKUs: "Ausschließlich typisierte Wertetabellen
mit je einem zusammengesetzten Index auf `(product_id, attribute_definition_id)` ermöglichen
B-Tree-Abfragen bei 10 000+ SKUs ohne Cast-Ausdrücke zur Laufzeit" (ADR-0004).

## Beschreibung
`AttributeDefinition` beschreibt ein einzelnes Attribut mit Datentyp, optionaler Einheit,
Validierungsregeln und Flags. Globale Definitionen (`scope = GLOBAL`) sind plattformweit sichtbar;
workspace-eigene Definitionen (`scope = WORKSPACE`) sind auf einen Mandanten beschränkt;
ererbte Definitionen (`scope = INHERITED`) stammen von einem `ClassificationNode`. `AttributeGroup`
bündelt thematisch zusammengehörige Definitionen. `AttributeSet` (workspace-scoped) ordnet einer
Kombination aus `ClassificationNode` und/oder `kind`-Enum eine Menge von `AttributeGroup`-Einträgen
zu, inklusive Pflichtfeld-Flag und Validierungsregeln.

## Acceptance Criteria

### AC-1: AttributeDefinition-Datentypen
- [ ] `AttributeDefinition` unterstützt die Datentypen `string`, `int`, `decimal`, `bool`, `enum`, `measure`, `reference` und `json`.
- [ ] Eine `AttributeDefinition` mit Datentyp `decimal` oder `measure` trägt optional einen FK auf `core.Unit`.
- [ ] Eine `AttributeDefinition` mit Datentyp `enum` trägt eine nicht-leere Liste erlaubter Enum-Werte.
- [ ] Das System weist eine `AttributeDefinition` mit Datentyp `enum` ohne Enum-Werte-Liste ab.

### AC-2: Scope-Flag
- [ ] Jede `AttributeDefinition` trägt genau einen `scope`-Wert aus `{GLOBAL, WORKSPACE, INHERITED}`.
- [ ] `GLOBAL`-Definitionen sind für alle Workspaces lesbar; nur Superuser legen sie an oder bearbeiten sie.
- [ ] `WORKSPACE`-Definitionen sind ausschließlich für den Workspace sichtbar, dem sie gehören.
- [ ] `INHERITED`-Definitionen sind an einen `ClassificationNode` gebunden; sie sind für alle Workspaces lesbar, die das Produkt unter diesem Knoten klassifizieren.

### AC-3: Validierungsregeln
- [ ] `AttributeDefinition` trägt optionale Validierungsregeln: `min`, `max` (für numerische Typen), `regex` (für `string`), Enum-Werte-Liste (für `enum`).
- [ ] Das System wendet die Validierungsregeln beim Speichern eines Attributwerts an und weist ungültige Werte ab.

### AC-4: Flags
- [ ] `is_localized`-Flag auf `AttributeDefinition` gibt an, ob der Wert sprachabhängig gespeichert wird.
- [ ] `is_required`-Flag auf `AttributeDefinition` gibt an, ob ein Attributwert für ein Produkt Pflicht ist.
- [ ] `is_multivalued`-Flag auf `AttributeDefinition` gibt an, ob mehrere Werte pro Produkt erlaubt sind.

### AC-5: AttributeGroup und AttributeSet
- [ ] `AttributeGroup` trägt einen Namen und bündelt mindestens eine `AttributeDefinition`.
- [ ] `AttributeSet` trägt FK auf `ClassificationNode` (optional) und/oder `kind`-Enum (optional); mindestens eines der beiden ist gesetzt.
- [ ] Ein Produkt, das unter einem `ClassificationNode` eingehängt ist, erbt automatisch alle `AttributeGroup`-Einträge des zugehörigen `AttributeSet`.
- [ ] Das Anlegen neuer `AttributeGroup`- und `AttributeSet`-Einträge erfordert keine Code-Änderung und keine Schema-Migration.

### AC-6: Workspace-Isolation
- [ ] Jede Datenbankabfrage auf `WORKSPACE`-scoped `AttributeDefinition`, `AttributeGroup` und `AttributeSet` filtert automatisch nach `workspace`.
- [ ] Ein automatisierter Test verifiziert, dass workspace-eigene Attributdefinitionen aus Workspace A nicht in Abfragen aus Workspace B erscheinen.

## Quality Attributes
- **Skalierung**: Das System unterstützt mindestens 200 `AttributeDefinition`-Einträge pro Workspace ohne Degradation der Formular-Metadaten-Abfrage.
- **Datenintegrität**: Das Löschen einer `AttributeDefinition` schlägt fehl, wenn noch Attributwerte (in getypten Wertetabellen) darauf verweisen.

## Betroffene Komponenten
- Backend: `koalixcrm/products/models/attribute_definition.py`, `attribute_group.py`, `attribute_set.py`, DRF-ViewSets, Validierungslogik
- Frontend: Dynamisches Produktbearbeitungsformular, das `AttributeSet`-Metadaten vom Backend liest (über DRF-Endpunkte, ADR-0002)
- Deployment: GLOBAL-scope-Fixtures für GS1-GPC/UNSPSC-Attribute als initialer Seed
