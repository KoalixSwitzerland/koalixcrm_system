# REQ-0014: Das System verknüpft Produkte mit Lieferanten über das Party-Rollenmodell

## Lizenzseite
Open-Source-Backend (`/app/koalixcrm`)

## Quelle
ADR-0006 (Beschaffung und Stücklisten), ADR-0001 (Kontakt- und Partei-Datenmodell)

## Why
Lieferanten sind im Party-Modell (ADR-0001) bereits als `PartyRole.role_type = 'supplier'`
abgebildet. Ein separates Lieferantenmodell würde die Kontaktmodellierung duplizieren und die
aus ADR-0001 stammende Rollenstruktur verletzen: "Die Wiederverwendung von `Party` als
Lieferantenrepräsentation vermeidet doppelte Kontaktmodellierung und hält `ProductSupply`
konsistent mit dem in ADR-0001 etablierten Rollenmodell" (ADR-0006).

## Beschreibung
`ProductSupply` (workspace-scoped) verknüpft ein `Product` mit einem Lieferanten-`Party`, der
die Rolle `PartyRole.role_type = 'supplier'` trägt. `ProductSupply` hält Lieferanten-SKU,
Lieferzeit, Mindestbestellmenge (MOQ) und Einkaufspreis. Workspace-scoped Entitäten erben den
`WorkspaceScopedModel`-Mechanismus: "Tenant-owned data inherits `WorkspaceScopedModel` and is
filtered by `request.active_workspace`" (ADR-0001).

## Acceptance Criteria

### AC-1: Datenbankstruktur
- [ ] `ProductSupply` trägt einen FK auf `Product`, einen FK auf `Party`, einen Lieferanten-SKU-String, eine Lieferzeit (Ganzzahl in Werktagen), eine Mindestbestellmenge (`moq`, positive Dezimalzahl) und einen Einkaufspreis.
- [ ] Ein `ProductSupply`-Eintrag ohne FK auf eine existierende `Party` wird vom System abgewiesen.

### AC-2: Lieferantenrolle
- [ ] Das System weist einen `ProductSupply`-Eintrag ab, dessen `Party` keine aktive `PartyRole` mit `role_type = 'supplier'` trägt.
- [ ] Die Prüfung der Lieferantenrolle erfolgt in der Applikationsschicht (Serializer-Validator oder Service), nicht als Datenbankconstraint.

### AC-3: Workspace-Isolation
- [ ] Jede Datenbankabfrage auf `ProductSupply` filtert automatisch nach `workspace`.
- [ ] Ein automatisierter Test verifiziert, dass `ProductSupply`-Einträge aus Workspace A nicht in Abfragen aus Workspace B erscheinen.

### AC-4: Mehrtfachlieferanten
- [ ] Ein Produkt hat mehrere `ProductSupply`-Einträge (ein Eintrag pro Lieferant).
- [ ] Die Kombination `(product, party)` ist eindeutig; das System weist einen zweiten `ProductSupply`-Eintrag für dieselbe Kombination ab.

## Quality Attributes
- **Datenintegrität**: Das Löschen einer `Party` schlägt fehl, wenn noch `ProductSupply`-Einträge auf sie verweisen.
- **Datenintegrität**: Das Löschen eines `Product` schlägt fehl, wenn noch `ProductSupply`-Einträge darauf verweisen.

## Betroffene Komponenten
- Backend: `koalixcrm/products/models/product_supply.py`, Lieferantenrollen-Validator, DRF-Serializer und ViewSet
- Frontend: Lieferantenverknüpfung in der Produktdetailansicht (über DRF-Endpunkte)
- Deployment: keine Infrastrukturänderung

## Nicht im Scope dieser Anforderung
- Stücklistenmodellierung (Gegenstand von REQ-0015).
- Bestellwesen und Lieferantenauswertung (Gegenstand der `contracts`-Anforderungen).

## Abhängigkeiten
- REQ-0001 (Product-Backbone)
- ADR-0006 (Beschaffungsentscheidung)
- ADR-0001 (Party-Rollenmodell, WorkspaceScopedModel-Mechanismus)
