# REQ-0010: Das System speichert Attributwerte in getypten Tabellen mit B-Tree-Indizes

## Lizenzseite
Open-Source-Backend (`/app/koalixcrm`)

## Quelle
ADR-0004 (Klassifizierung und erweiterbare Attribute), OQ-0003

## Why
Eine polymorphe EAV-Tabelle mit Cast-Ausdrücken zur Laufzeit bricht die Abfrageperformance bei
10 000+ SKUs, weil Cast-Ausdrücke keine B-Tree-Indizes nutzen. Typisierte Wertetabellen mit
je einem zusammengesetzten Index auf `(product_id, attribute_definition_id)` sind die
architektonische Entscheidung aus ADR-0004, um diese Performance-Anforderung zu erfüllen.

## Beschreibung
Attributwerte werden in sechs typisierten Wertetabellen gespeichert: `ProductAttributeDecimal`,
`ProductAttributeString`, `ProductAttributeEnum`, `ProductAttributeBool`,
`ProductAttributeReference` und `ProductAttributeInt`. Jede Tabelle trägt einen zusammengesetzten
Index auf `(product_id, attribute_definition_id)`.

Ein optionaler denormalisierter JSONB-Spiegel pro Produkt unterstützt leseintensive Such- und
Listenpfade. Der Spiegel wird von einem Django-Signal oder einer Celery-Task aktuell gehalten,
sobald ein Attributwert gespeichert oder geändert wird.

Alle Wertetabellen sind workspace-scoped: "Tenant-owned data inherits `WorkspaceScopedModel`
and is filtered by `request.active_workspace`" (ADR-0001).

## Acceptance Criteria

### AC-1: Tabellen und Datentypen
- [ ] `ProductAttributeDecimal` speichert Dezimalzahlen und trägt optional einen FK auf `core.Unit`.
- [ ] `ProductAttributeString` speichert Zeichenketten.
- [ ] `ProductAttributeEnum` speichert Enum-Schlüssel als Zeichenkette; der Schlüssel muss einem der Enum-Werte der zugehörigen `AttributeDefinition` entsprechen.
- [ ] `ProductAttributeBool` speichert Boolean-Werte.
- [ ] `ProductAttributeReference` speichert einen FK auf eine Lookup-Entität.
- [ ] `ProductAttributeInt` speichert Ganzzahlen.

### AC-2: Indizes
- [ ] Jede der sechs Wertetabellen trägt einen zusammengesetzten Datenbankindex auf `(product_id, attribute_definition_id)`.
- [ ] Ein automatisierter Test verifiziert, dass der Index auf jeder Wertetabelle existiert.

### AC-3: Typsicherheit
- [ ] Das System weist einen Attributwert ab, dessen Datentyp nicht mit dem `data_type`-Feld der zugehörigen `AttributeDefinition` übereinstimmt.
- [ ] Das System wendet die Validierungsregeln der `AttributeDefinition` (min, max, regex, Enum-Werte-Liste) beim Speichern des Attributwerts an.

### AC-4: JSONB-Spiegel
- [ ] Jedes `Product`-Objekt trägt ein `attribute_mirror`-JSONB-Feld, das alle aktuellen Attributwerte als flache Schlüssel-Wert-Struktur enthält.
- [ ] Der JSONB-Spiegel wird nach jedem Speichern oder Löschen eines Attributwerts innerhalb derselben Transaktion oder über einen asynchronen Task aktualisiert.
- [ ] Ein GIN-Index auf dem `attribute_mirror`-Feld ist vorhanden.
- [ ] Die maximale Verzögerung zwischen Schreiben eines Attributwerts und Aktualiserung des JSONB-Spiegels ist konfigurierbar (synchron oder asynchron via Celery).

### AC-5: Workspace-Isolation
- [ ] Jede Datenbankabfrage auf alle sechs Wertetabellen filtert automatisch nach `workspace`.
- [ ] Ein automatisierter Test verifiziert, dass Attributwerte aus Workspace A nicht in Abfragen aus Workspace B erscheinen.

## Quality Attributes
- **Performance**: Eine Attributfilter-Abfrage (z. B. `ProductAttributeDecimal` mit `attribute_definition_id = X` und `value > Y`) bei 10 000 Produkten im Workspace liefert HTTP 200 in p95 < 300 ms (gemessen am zusammengesetzten Index; Szenario aus QAS-0001).
- **Performance**: Eine Listenabfrage mit GIN-Index auf `attribute_mirror` bei 10 000 Produkten und 200 Attributen pro Produkt liefert HTTP 200 in p95 < 500 ms (Szenario aus QAS-0002).
- **Datenintegrität**: Das Löschen einer `AttributeDefinition` schlägt fehl, wenn noch Werte in einer der sechs Wertetabellen darauf verweisen.

## Betroffene Komponenten
- Backend: `koalixcrm/products/models/attribute_values.py` (sechs Modelle), Index-Deklarationen in Migrations, Signal/Celery-Task für JSONB-Spiegel, DRF-Serializer
- Frontend: Produktbearbeitungsformular liest und schreibt Attributwerte über DRF-Endpunkte
- Deployment: Celery-Worker für asynchrone Spiegel-Aktualisierung (wenn asynchron konfiguriert)

## Nicht im Scope dieser Anforderung
- Die Entscheidung über partielle Indizes oder weitergehende Indexstrategien (Gegenstand von QAS-0001 bis QAS-0003 und der Architekten-Review, blockiert durch OQ-0003).
- Volltextsuche auf Attributwerten (Gegenstand eines separaten Anforderungsdokuments).
