# koalixcrm — Consolidated Glossary

This glossary consolidates all domain-specific terms, acronyms, and abbreviations used across the
koalixcrm documentation. Terms are listed in alphabetical order. The Reference column links to the
document where the term is defined or used in depth.

---

| Term / Acronym | Full Form | Description | Reference |
|---|---|---|---|
| `active_workspace` | — | Request-scoped Python attribute set by `WorkspaceContextMiddleware` on every incoming HTTP request; holds the currently selected `Workspace` instance and is read by views, admin classes, and `WorkspaceAwareManager`. | [QQ_LL_Doc_Core_Infrastructure.md](../05_building_block_view/koalixcrm/core/QQ_LL_Doc_Core_Infrastructure.md) |
| Account | — | A ledger account in the double-entry bookkeeping system. Has an `account_type` of E (Earnings), S (Spendings), L (Liabilities), or A (Assets). | [QQ_ML_Doc_Accounting.md](../05_building_block_view/koalixcrm/accounting/QQ_ML_Doc_Accounting.md) |
| AccountingPeriod | — | A fiscal calendar period (e.g. a financial year or quarter) that scopes all bookings within it. Used as the basis for P&L and balance-sheet PDF reports. | [QQ_ML_Doc_Accounting.md](../05_building_block_view/koalixcrm/accounting/QQ_ML_Doc_Accounting.md) |
| Agreement | — | A negotiated cost-rate cap binding a `Resource` to a `Task` over a date range; activates when its `AgreementStatus.is_agreed` flag is true. | Assignment table | — | A join table that links a canonical contact record (address, e-mail, phone number) to a `Party`, annotating the link with a purpose code and an optional validity window. | [QQ_ML_Doc_Contacts.md](../05_building_block_view/koalixcrm/contacts/QQ_ML_Doc_Contacts.md) |

| `azp` | Authorized Party | JWT claim identifying the OAuth 2.0 client to which the token was issued; inspected by `CeleryWorkerM2MAuthentication` to validate M2M tokens. | [QQ_ML_Doc_Auth.md](../05_building_block_view/koalixcrm/auth/QQ_ML_Doc_Auth.md) |
| Backfill | — | The one-time data migration (contacts migrations `0005`-`0009`) that created `Party`, `Organization`, and `PartyContact` rows from the legacy contacts schema before the destructive v2.0.0 cutover. | [QQ_ML_Doc_Contacts.md](../05_building_block_view/koalixcrm/contacts/QQ_ML_Doc_Contacts.md) |

| Billing Cycle | — | The `CustomerBillingCycle` record on a party that specifies the number of days until payment is due (`time_to_payment_date`). | Booking | — | A double-entry record that transfers an amount from one ledger `Account` to another within an `AccountingPeriod`; optionally linked to an `Invoice` as its booking reference. | [QQ_ML_Doc_Accounting.md](../05_building_block_view/koalixcrm/accounting/QQ_ML_Doc_Accounting.md) |
| Broker | — | The message transport used by Celery to queue tasks; in koalixcrm this is AWS SQS accessed via the `kombu` library. | [QQ_ML_Doc_Microservices.md](../05_building_block_view/koalixcrm_microservices/QQ_ML_Doc_Microservices.md) |
